# AudioPlaybackConnector
[English](https://github.com/ysc3839/AudioPlaybackConnector/blob/master/README.md) | **简体中文**

Windows 10 2004+ 蓝牙音频接收 (A2DP Sink) 连接工具。

微软在 Windows 10 2004 加入了蓝牙 A2DP Sink 支持。但是需要第三方软件来管理连接。\
已经有了一个可以实现此功能的 app。但是它不可以隐藏到通知区域，而且不开源。\
所以我写了这个 app，提供一个简单的，现代且开源的替代品。

# 使用方法
* 从 [releases](https://github.com/ysc3839/AudioPlaybackConnector/releases) 下载并运行 AudioPlaybackConnector。
* 在系统蓝牙设置中添加蓝牙设备。你可以右键点击通知区域的 AudioPlaybackConnector 图标然后选择“蓝牙设置”。
* 点击 AudioPlaybackConnector 图标然后选择想要连接的设备。
* 尽情享受吧！

右键托盘图标，选择“设置”：
* “开机启动”：启用后，在当前用户登录 Windows 时自动运行。请保持可执行文件的位置不变。
* “手机音频连接”：选择“暂时关闭”并点击“应用”，立即断开本程序的手机音频连接并停止重试；选择“启动”后，自动连接所选手机。
  启动时等待 Windows 实际报告音频通路已打开，不设置固定释放延迟，也不会仅因无声而自动断开重连。真正断开可能让手机播放器自动暂停，重新连接并不等于继续播放；请在手机恢复播放。
* “自动连接的手机”：从已配对且支持蓝牙音频的设备中选择手机。只有一个可用设备时会自动选中。
* 设置立即保存。手机暂时不在附近或打开失败时，保留已注册的音频接收服务以接受手机主动连接；手机蓝牙重新连上时立即尝试打开通路。轮询只作兜底，失败时逐渐延长间隔，最长一分钟。手动点击设备列表中的断开按钮也会暂停自动连接。

自动连接需要双方已完成配对，并且蓝牙认证正常。程序不会关闭电脑的蓝牙适配器，也不会解除手机配对。

部分 Windows 蓝牙音频会话在重连后虽显示已打开，却没有启动数据传输。激活接口返回成功也不代表已经传声，尤其是手机重连后稍晚才播放的情况。程序通过一个持续运行的音频后台线程监听会话创建和状态通知，并保留通知返回的会话引用，避免依赖可能滞后的枚举快照。

通路打开后，初始化保持“待验证”。如果已经测到真实手机声音，直接完成；否则对未静音且音量非零的手机会话做约 80 毫秒的静音切换并恢复原状态。接口成功但仍没有信号时，按受控间隔继续初始化（退避等待最长约一秒），手机延迟播放也不会因先前一次接口成功而漏过激活。测到声音后立即停止，不因后续正常安静片段反复操作。连续接口错误最多尝试三次。此步骤不关闭蓝牙，不调整音量，不影响其他应用；用户已静音、输出已静音或音量为零时不操作。关闭设置或通路失效会取消旧初始化任务。

如果仍然听不到手机声音，可在设置中点击“检测并修复无声”，并让手机持续播放音乐。程序先尝试会话激活并检测音量和信号，必要时最多重建一次手机音频连接；仍未检测到声音时会提示检查手机媒体音量和输出设备。正常启动不经过这个完整修复流程，暂停或静音也不会触发自动重连。电脑默认输出切换后，程序会重新建立自己的音频连接以跟随新设备。

“查看诊断日志”可以打开程序旁 `logs/AudioPlaybackConnector.log`。日志记录连接阶段、耗时、错误码、输出设备、音量和信号峰值，不录制声音，不记录歌曲内容；日志达到约 2 MB 时保留一个滚动备份。时间使用 UTC（结尾为 `Z`）。连接请求超过 30 秒会取消并按退避间隔重试。

本地构建前可运行 `python translate/generate_resources.py`，无需额外安装翻译库即可生成中文资源。

连接时序诊断：`OpenAsync` 返回成功与 `StateChanged(Opened)` 可能有短暂先后差异。程序保留同一个连接对象等待实际打开事件，不会因初始化阶段的 `Closed` 状态主动销毁连接。通路断开、打开失败或打开超时都保留已经启动的接收器；只有用户关闭、更换手机、设备被移除、注册失败或退出时才释放。实际有声音需以音频信号日志为准，单独的“蓝牙已连接”或“通路已打开”不代表已经收到音乐。
